## 3 — Policy (pure, host-tested)  *(DECIDED)*
**Files:** `src/dashboard/DashboardPolicy.h` · `src/dashboard/DashboardPolicy.cpp` · `test/dashboard_policy/CMakeLists.txt` ·
`test/dashboard_policy/DashboardPolicyTest.cpp` · `test/CMakeLists.txt`
- No Arduino or HAL includes. Input struct: enabled, local hour and minute, clock valid, battery %, floor %,
  quiet on/start/end, consecutive failures, retry limit, interval minutes.
- Output: `{ Screen screen; uint32_t timerSeconds; }`, where `Screen` is `Dashboard`, `FallbackQuiet`,
  `FallbackBattery` or `FallbackFailures`. Rules, in this order:
  1. Disabled → no dashboard, timer 0 (the caller sleeps as today).
  2. Battery floor on and battery < floor → `FallbackBattery`, timer 0 (button wake only).
  3. Quiet on, clock valid, local time inside [start, end) with midnight wrap → `FallbackQuiet`, timer =
     seconds until `end:00`.
  4. Failures ≥ retry limit → `FallbackFailures`, timer = interval (it keeps trying).
  5. Else → `Dashboard`, timer = interval.
- An invalid clock (no RTC time, or year < 2026) never counts as quiet.
- Tests: wrap across midnight (22→7 at 23:30, 03:00, 07:00, 21:59), start == end (treated as no quiet), battery
  exactly at floor (not below), floor Off, failures at limit −1 and at limit, every interval value.

## 4 — State, image files and sources  *(DECIDED)*
**Files:** `src/dashboard/DashboardState.h/.cpp` · `src/dashboard/DashboardImageStore.h/.cpp` ·
`src/dashboard/DashboardSource.h/.cpp` · `src/dashboard/LocalFolderSource.h/.cpp`
- Files under `/.crosspoint/dashboard/`:
  - `current.bmp`: the last good image.
  - `next.bmp`: being published.
  - `frame.bin`: the raw framebuffer that is on the glass, `renderer` buffer size, written after every draw.
  - `state.json`: the state below.
- `DashboardState` holds: `lastSuccessUtc` (epoch seconds), `lastFilename[96]`, `consecutiveFailures`,
  `lastReason[24]`, `screenShows` (Dashboard / Banner / Fallback kind), `fastRefreshesSinceHalf`,
  `lastNtpSyncUtc`, `localFolderIndex`. JSON through ArduinoJson. A missing or corrupt file → defaults, logged.
- Keep all state on SD, not in RTC memory. It survives power loss and there is one store to debug. Rejected: an
  `RTC_NOINIT_ATTR` struct.
- **Interfaces this handover creates** (handover 003 implements against them):
  ```cpp
  enum class DashboardFetch : uint8_t { Updated, Unchanged, Failed };
  struct DashboardFetchResult { DashboardFetch kind; char reason[24]; };
  class DashboardSource {
   public:
    virtual ~DashboardSource() = default;
    // Writes /.crosspoint/dashboard/next.bmp and calls DashboardImageStore::publishNext() on success.
    virtual DashboardFetchResult fetch(DashboardState& state) = 0;
    virtual bool needsWifi() const = 0;
  };
  DashboardSource& selectDashboardSource();  // URL empty → LocalFolderSource. 003 adds TrmnlSource.
  ```
- `DashboardImageStore::publishNext()` opens `next.bmp` and requires `Bitmap::parseHeaders()` to succeed. It then
  swaps it over `current.bmp` with the `DownloadFileSwap::publish` pattern (`src/network/DownloadFileSwap.h:9-39`).
  On any failure `current.bmp` is untouched.
- `LocalFolderSource`: lists `*.bmp` in `/dashboard/` on the SD root, sorted by name. Each fetch copies the next
  one to `next.bmp` and publishes it. Return values: `Updated` normally; `Unchanged` with exactly one file whose
  name equals `lastFilename`; `Failed("no images")` when the folder is empty. `needsWifi()` is false. This is the
  hardware test source, and it stays in the product as the offline option.

## 7 — Sleep entry hook  *(DECIDED)*
**Files:** `src/activities/boot_sleep/SleepActivity.cpp` · `src/main.cpp` · `lib/hal/HalPowerManager.h/.cpp` ·
`src/dashboard/DashboardSleep.h/.cpp`
- `HalPowerManager::startDeepSleep` gains `uint32_t timerWakeSeconds = 0`. When non-zero, call
  `esp_sleep_enable_timer_wakeup(seconds * 1000000ULL)` between `armPowerButtonWakeup()` (`:166`) and
  `gpio_deep_sleep_hold_en()` (`:167`). Guard it with `#ifndef SIMULATOR`. Existing callers pass nothing.
- In `SleepActivity::onEnter`, before the mode dispatch (`:515-588`), add the flag-gated hook:
  `if (DashboardSleep::drawOnSleepEntry(renderer)) return;`. It returns true when the policy screen is
  `Dashboard` and `current.bmp` exists. It draws `current.bmp` (with a banner when failures > 0), uses HALF
  refresh (no restored frame on this path), and writes `frame.bin`. Otherwise it returns false, and the normal
  sleep screen draws. That normal screen is the fallback, because the fallback is the existing Sleep Screen setting.
- In `enterDeepSleep` (`main.cpp:1087-1139`), when the flag is on and the dashboard is enabled, pass
  `DashboardSleep::timerOnSleepEntry()` to `startDeepSleep`. That value is 2 s when the policy screen is
  `Dashboard` (so the first fetch happens right after the device sleeps), and the policy timer otherwise.
- Save `frame.bin` also when the fallback screen was drawn. The next wake can then restore it.
- When the dashboard is enabled, Quick Resume's `sleep_frame.bin` logic is unchanged. The dashboard uses its own
  `frame.bin`.

## 8 — Timer-wake boot path  *(DECIDED)*
**Files:** `src/main.cpp` · `src/dashboard/DashboardWake.h/.cpp`
- Extract `enterDeepSleep`'s hardware tail (`main.cpp:1130-1138`: scan-token save, `Storage.shutdown`, tilt
  sleep, `display.deepSleep`, NVS mirror, `startDeepSleep`) into `static void sleepHardware(uint32_t timerSeconds)`.
  `enterDeepSleep` calls it, with no behaviour change.
- In `setup()`, right after `UITheme::getInstance().reload()` (`:1365`), add a flag-gated branch: when
  `rawWakeupCause == ESP_SLEEP_WAKEUP_TIMER` and `SETTINGS.dashboardEnabled`, call
  `const uint32_t t = DashboardWake::run();` then `sleepHardware(t);`. Steps the branch skips:
  - frontlight restore (call `Frontlight.begin(..., false)`, so the light stays off);
  - quick-lock handling;
  - `BootResume`;
  - `showBootScreen` writes;
  - every `goTo*` route.

  A timer wake with the dashboard disabled sleeps again at once with timer 0.
- `DashboardWake::run()` sequence:
  1. Start a backstop `esp_timer` one-shot at 60 s. When it fires it arms the interval timer and calls
     `esp_deep_sleep_start()` directly. A hang can never keep the device awake.
  2. `setupDisplayAndFonts(seamless = true, loadReaderResources = false, ...)`.
  3. Load `frame.bin` into the framebuffer. If it loads, call `display.restoreVisibleFrame()` and remember the
     result for step 6's refresh mode.
  4. Load state and evaluate the policy.
  5. Act on the policy result:
     - Fallback with the same kind as `screenShows`: draw nothing.
     - Fallback of a new kind: construct `SleepActivity(renderer, mappedInputManager, false)` and call
       `onEnter()`. The hook from step 7 returns false in fallback states, so the normal sleep screen draws.
  6. `Dashboard` path:
     - Connect Wi-Fi when `needsWifi()`.
     - NTP sync when the clock is invalid or `lastNtpSyncUtc` is over 24 h old.
     - `fetch()`.
     - On `Updated`: reset failures, draw with no banner.
     - On `Unchanged`: draw only if `screenShows` is Banner or Fallback, to remove the banner.
     - On `Failed`: increment failures. If that reaches the retry limit, draw the fallback screen. Otherwise
       draw the banner if it is not already shown.
     - Save state.
  7. `WifiConnector::disconnectAndOff()`. Cancel the backstop. Return the policy timer, recomputed after the
     failure count changed.
- Log one line per wake: wake reason, policy screen, fetch result, refresh mode, awake milliseconds.
- In the simulator, the `esp_sleep_get_wakeup_cause()` stub returns `ESP_SLEEP_WAKEUP_TIMER` when env
  `CROSSPOINT_SIM_TIMER_WAKE=1` is set. That is the only simulator change.

## Decisions — locked ✅
- The dashboard is a toggle in its own tab, and the fallback is the existing Sleep Screen setting. Rejected: a new
  `SLEEP_SCREEN_MODE` value, because it would need a second picker for the fallback.
- Settings live in `CrossPointSettings` under the flag. Rejected: a separate store, because the tab and the web
  portal would need custom code.
- The API key is obfuscated on SD and masked in the web GET. Rejected: plain text as cross-trmnl does.
- All state is on SD in `state.json`. Rejected: RTC memory (lost on power loss, a second store).
- "Refresh now" sleeps with a 2 s timer. Rejected: a foreground Wi-Fi refresh, which needs the network-boot
  restart and a second code path.
- On sleep entry the device draws the cached image and wakes 2 s later to fetch. Rejected: fetching before sleep,
  which leaves the reader on screen for up to 15 s with Wi-Fi up.
- A periodic HALF refresh every 30 FAST updates and after any fallback. Rejected: FAST forever (ghosting) and HALF
  always (flash).
- 60 s backstop timer plus per-step timeouts. Rejected: timeouts alone, because one unbounded call would drain the battery.
- The local-folder source stays as the offline option. Rejected: a test-only stub.
- Timer is a parameter of `startDeepSleep`. Rejected: a global setter, which a later caller could forget to reset.
